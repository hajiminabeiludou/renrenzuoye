# v1.1 文件存储模块审核记录

审核人：尚渊

被审核版本：`v1.1-original`

建议修复版本：`v1.1-fixed`

## 审核范围

本次审核重点检查文件读写模块，包括 `file_io.c`、`file_io.h`、`storage.cpp` 和 `data/*.dat` 初始数据文件。

## 审核意见

1. `ensure_directory` 对 `_mkdir` 的执行结果没有区分处理，当前只要调用过就返回成功。如果路径无效、权限不足或被同名文件占用，保存逻辑仍会继续执行，后续排查问题会比较困难。建议判断 `errno == EEXIST` 时视为成功，其他错误返回失败。

2. `loadAll` 调用了 `loadUsers`、`loadCategories`、`loadItems`、`loadClaims`，但没有使用这些函数的返回值，最后固定返回 `true`。如果某个数据文件缺失或损坏，调用方无法知道加载失败。建议让 `loadAll` 汇总加载结果，或者至少在首次启动缺少数据文件时给出明确处理策略。

3. `seedIfEmpty` 只判断 `state.users` 是否为空。如果 `users.dat` 丢失但 `categories.dat` 或 `items.dat` 还存在，重新初始化时可能追加重复分类或样例物品。建议种子数据初始化前统一检查四类数据是否都为空，或者在初始化前清空旧的部分数据。

4. 当前存储格式直接使用 `|` 分隔字段，虽然保存时会把字段中的 `|` 替换为 `/`，但加载时没有记录字段转义规则。这个版本可以接受，但后续如果要保存更复杂的描述文本，建议在说明文档中写清楚字段限制。

## 审核结论

v1.1 已经完成基础文件存储能力，模块划分清楚，能够作为后续登录、发布、审核业务的持久化基础。建议修复目录创建返回值、加载结果返回值和部分数据缺失时的初始化逻辑后，再提交 `v1.1-reviewed-storage`。
