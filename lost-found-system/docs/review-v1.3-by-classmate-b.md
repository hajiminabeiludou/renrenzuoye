# v1.3 图形界面模块审核记录

审核人：尚渊

被审核版本：`v1.3-original-gui`

建议修复版本：`v1.3-reviewed-gui`

## 审核范围

本次审核重点检查 `gui.cpp` 中新增的 Win32 图形界面，包括登录注册窗口、学生端窗口、管理员端窗口、数据刷新和保存逻辑。

## 审核意见

1. GUI 已经拆分为登录注册、学生端和管理员端三个窗口，整体结构符合“学生负责发布和认领、管理员负责审核”的要求。但代码中仍然通过 `role == 0/1` 判断角色，建议改为 `ROLE_STUDENT` 和 `ROLE_ADMIN`。

2. GUI 中仍有较多状态魔法数字，例如物品状态 `0/1/2`、认领状态 `0/1/2`。v1.0 已经定义枚举，建议统一使用 `ITEM_OPEN`、`ITEM_PROCESSING`、`ITEM_FINISHED`、`CLAIM_PENDING`、`CLAIM_APPROVED`、`CLAIM_REJECTED`。

3. 多处调用 `saveAll(g_state)` 后没有检查返回值。若文件被占用或目录权限异常，界面仍提示发布、认领或审核成功，存在数据丢失风险。

4. 注册、发布和审核流程虽然有部分校验，但还不够统一。建议对用户名、密码、姓名、标题、地点、描述、认领理由和审核备注都进行不能为空校验。

5. 学生发布信息时，分类下拉框使用当前选中序号计算分类编号。如果后续分类排序或禁用分类发生变化，可能选错分类。建议直接保存分类 id，或至少确认选中项有效。

6. 程序启动时调用 `loadAll` 后没有根据返回值提示数据文件是否缺失或损坏。建议和 v1.2 修改版保持一致，启动时给出数据状态提示。

## 审核结论

v1.3 原始版已经完成图形界面雏形，登录注册、学生端和管理员端的基本功能都能覆盖作业要求，演示效果比控制台版本更直观。

但当前版本在枚举常量使用、保存失败处理、输入校验和启动数据提示方面还需要修复。建议按以上意见提交 `v1.3-reviewed-gui` 修改版。
